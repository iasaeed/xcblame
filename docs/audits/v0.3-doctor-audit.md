# v0.3 "Doctor" audit: five real projects (anonymized)

The §11 v0.3 exit criterion asks for a written audit checklist that matches `doctor` output on real projects. This file
records the procedure and an anonymized summary. Project names, paths and identifiers are never written here; each
project is described by its shape only.

## Procedure

1. Before any `doctor` run, the auditor writes the expected outcome of every catalog rule (finding, pass, N/A,
   suppressed) per project by hand, from the project files (pbxproj, xcconfigs, schemes, Podfile and lockfile,
   `Package.resolved`), the xcspec defaults, and `xcodebuild -showBuildSettings` run on a scratch copy.
2. Tree hashes (paths, sizes, nanosecond mtimes) of each project are taken before and after, with and without `.git`.
3. `xcblame doctor --format json` runs once cold (empty settings cache) and once cached; the outcome lists are compared
   with the expectations rule by rule. Each mismatch is judged: tool wrong, expectation wrong, or either defensible.
4. Fixes are made on fixtures and scratch copies only (never on the audited projects); the auditor then re-runs step 3
   and fills the "after" column.
