- **§11 v0.3 exit criteria.** "On 5 OSS projects, a written audit checklist … matches `doctor` output exactly" does not exist. Only synthetic fixtures are checked.
- **v0.3 scope "Tier-1 SET, …, ENV-\*".** ENV-008 (S+D, Xcode 26.x macro-plugin planning) is not in the catalog. The integration note mentions SET-011 but not DEP-004. SET-024's static part, SET-033, SET-034, PHASE-010 (S+D) and DEP-011 are absent without a decision line.
- **V12** ("estimated saving ≤ measured cost") is still `notApplicable` under `analyze`, although v0.3 findings now carry measured seconds.
- **RULES.md §10 shadowing.** The `cli` option is printed as "once the oracle confirms the value changes", but the oracle check with the wrapper xcconfig (§7.5) is never run. That is acceptable as v0.6 work, but no decision paragraph records the deferral.
- **§7.5 "list-typed keys start with `$(inherited)`" and the plan id in overlay lines** are not implemented. Overlay lines are `KEY = VALUE // xcblame <id>` with no plan id.
- **§7.4 "including package targets".** Remote package targets are absent and local ones carry only `SWIFT_VERSION`. Documented in the Lane B notes, but `project.packageTargets` counts them as if their settings were read.

## Test gaps

- `RulesCatalogTests.testSpecsCarryTheRowVerbatim` never checks bracketed mixed tags (`[S/K]`), which is how finding 6 got through.
- Nothing tests a shadowed `+V` finding (1), a Pods-xcconfig shadow (2), an SDK-conditional value on a dependency target of another platform (3), or a conditional-before-unconditional xcconfig pair. The Precedence fixture only covers unconditional-then-conditional.
- No test covers git-ignoring and size of `.xcblame/cache` (4), the reuse of the user's DerivedData checkouts under failure or concurrency (5), or the doctor CLI with an unknown `--rules` id plus `--fail-on` (11).
- `SettingsOracleTests.testLargeFixtureBatchUnderFiveSeconds` asserts wall time under 5 s. It ran 3.65 s cold here on a fast machine, so it is likely flaky on 3-core CI runners. `FixtureProjectTests` and the AcmeApp oracle tests need network for the first package resolve (they skip offline). Both depend on the machine and network rather than the code.
- Measured paths in `analyze` (SET-005 multi-arch, PHASE-001 script cost, DEP-003) are tested with synthetic task titles that contain the arch or phase name. Real Xcode Swift titles do not (8).

## Summary

- 18 findings: 0 blocker, 5 major, 13 minor. Majors 1-4 CONFIRMED by running fixture copies; 5 PLAUSIBLE.
- The read-only guarantee holds for project files: the tree snapshot was identical after doctor on all seven fixtures.
- The weak spots are where the engine has to follow RULES.md literally: a shadowed `+V` rule skips verify, and a Pods-managed xcconfig is treated as an editable project value. The other is the oracle's generated scheme, which evaluates iOS dependency targets as macOS.
- The settings cache puts hundreds of MB, unignored and unpruned, into the user's repo on a plain `doctor` or `analyze`.

**Verdict: FIX FIRST** (findings 1-4; 5 before `analyze` and `doctor` run by default on real package projects).
