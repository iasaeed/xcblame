## Requirement gaps

- §6.2 step 4: per-task slack (latest start − earliest start) is not computed anywhere, and no decision paragraph drops it. §6.2 step 3: `dynamicTaskRequest` ordering is left to a ponytail comment.
- §6.11 V9 and V11 cannot fail as implemented. Exact rows are a subset of the same target's compile tasks, so V9 always holds. V11 re-checks the very counts `BuildKind.classify` branched on. V3's "DAG edges consistent" clause is also tautological, because inconsistent DAGs are dropped before V3 runs. These are restatements, not independent checks.
- §5.11 "matched … whose command keys cover ≥ 95 %": snapshot and explicit descriptions skip the threshold (finding 3), and the runner picks by mtime instead of by signature (finding 2).
- §8.2.3: the cap is not hard and size can fail the command (finding 5). No stderr warning on truncation.
- §8.3: HTML reports are neither git-ignored (from `analyze`) nor pruned. The v0.2 code also writes `.xcblame/.gitignore` containing `*` and never rewrites an existing one. That will also ignore the committed `.xcblame/baseline.json` and `config.json` planned for v0.4 (§3.1, §3.2).
- §6.7: `cached` and `previews` are never produced. `clean-action` was added (Lane A note), but the `build.kind` row of the schema table and DESIGN §6.7 do not list it.
- §8.2.2: the `lanes ≤ 4000` limit can be exceeded (finding 9).
- §6.4: `estimated` rows are not produced. This is recorded only in the schema doc's Lane A notes, not in a DESIGN v0.2 decision paragraph.

## Test gaps

- The consistency test uses a scrambled manifest. Nothing tests an unmodified foreign description, which is exactly the case that slips through (finding 3).
- The 50k performance test has no build description, so the quadratic DAG and what-if are never timed (finding 4). No hand-built DAG with a known longest path and what-if serves as an oracle; the assertions are fixture shapes.
- The fake xcodebuild writes exactly one description, so the reused-description path of `build` (finding 2) and concurrent logs are never tested.
- No robustness inputs for the new Int conversions (1e300, ±inf, span overflow) in History, TaskIndex or Utilization (finding 1).
- No CLI test of html truncation versus V13 and the exit code (finding 5). None for `.xcblame/reports` being git-ignored, for `build --html --no-redact`, or for redaction of a foreign home.
- The V9 and V11 tests cannot fail by construction (see the requirement gaps).
- Checked and found sound: no weakened assertions in the diff (the four removed `XCT*` lines were replaced by stricter ones). Determinism holds: 3 runs gave byte-identical JSON. Hostile saved reports (1e308, negatives, empty `taskIds`) render text, json and html without crashing. Snapshot and history pruning do not follow a symlinked `snapshots/`: Foundation's URL listing fails with ENOTDIR, so nothing outside is deleted. The template has no `innerHTML`, string-built JS, inline handlers or network references, and the CSP is correct. The blob is escaped for `</`, `<!--` and U+2028/9, and placeholders are filled before `{{DATA}}`.

## Summary

- 14 findings: 0 blocker, 5 major, 9 minor. Majors 1-5 are all CONFIRMED by running.
- The core risk sits where the build description meets the build. `build` can snapshot another description, the locator and consistency check accept a 14 %-coverage description, and the DAG grows quadratically on gate-heavy manifests.
- New Int conversions in History, TaskIndex and Utilization reopen the crash-on-extreme-input class from v0.1. In `build` that crash changes xcodebuild's exit code.
- HTML truncation works but still fails the command through V13.

**Verdict: FIX FIRST** (findings 1-5).
