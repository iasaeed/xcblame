# xcblame HTML reports: junior iOS developer read-through

Reader persona: 1 year of iOS, knows Xcode and Swift, has never heard of build-system internals.
Method: each page (`analyze`, `doctor`, `compare`, `trend`, `why`, "after" renders) rendered in headless Chrome, DOM text read top to bottom, screenshots viewed.
Format per item: section -> quoted text -> problem -> suggested wording or change.
Glossary note: the 65-term glossary exists, is reachable by dotted-underlined links, and the hash handler opens it. Most "unexplained term" items below are therefore terms that are NOT underlined/linked at the place of use, or are only in a hover `title`, or whose glossary definition still uses more jargon.

Common to all pages (listed once, referenced as C1..C8 below)

- C1. Header strip "What this shows / What to do" is repeated under every section, including sections that are empty ("doctor runs no build: this section needs a build log" on doctor) and hidden placeholders. Fine idea, but on pages with 108-row or 405-row tables it is the only summary. No "so what" sentence above the big tables.
- C2. Table footers say "showing 88 of 88 rows  [Show 200 more]" and then "Showing all 88 rows." On compare: "showing 200 of 395 rows [Show 200 more]" directly followed by "Showing all 395 rows." Contradictory; a junior will think 195 rows are missing or that the page is broken.
- C3. Superscript footnotes: "unknown¹" in every Type-check cell (88 times on analyze) with the reason only in a "Why some cells say unknown" list under the table, after a scroll of 88 rows. The reason is not next to the value. (Requirement: reason visible next to unknown.)
- C4. Every tile/summary uses `title=` hover text for the explanation of Log span, critical path, clean build, how-found, rule id, impact band, confidence, safe-to-try. Hover-only = hidden, and impossible on trackpad-free/touch/screenshot.
- C5. Footer/Notes use developer words: "null", "doctor document", "kind table 2026.10.1", "slf v11", "format v11", "layout commandLine", "Decode warnings", "Excluded nothing", "Signature 05e6f8da...".
- C6. Local source path rendered in the header of every page is a worktree path (`~/Projects/xcblame/.claude/worktrees/agent-.../fixtures/logs/...`). Prominent, meaningless to the reader (fixture artifact; real users would see their own path, so low priority, but the UUID `.xcactivitylog` file names are used as the *identity* of the builds on compare).
- C7. Colors carry meaning in the stacked bars (14 task kinds; the long tail is several indistinguishable greys). Legend text exists, but small segments (link, codesign, aux, copy, gate, other, validate) are all the same grey, so the legend cannot be matched by color.
- C8. Units: percentages without stated denominator (see analyze A5), "ms"/"s" mixed in one column (fine), "task time" vs "wall time" never reconciled for the reader in the findings.
